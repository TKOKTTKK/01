这个包是「两把密钥都放 Worker」的版本。

和上一版的区别
--------------
1. tronagg 的 key、TronGrid 的 key，现在都只写在 worker.js 里。
   页面（index.html）里一把都不剩，查看源码也搜不到。
2. 为了做到这一点，页面原本直连 api.trongrid.io 的链上请求，也改走本站同源转发：
     页面  ->  /trongrid/xxx  ->  https://api.trongrid.io/xxx （Worker 自动补 TRON-PRO-API-KEY）
3. 页面可见内容一个字没变（实测可见文字与原版完全一致），只在 <head> 里加了一小段
   请求转写脚本，把发往 TronGrid 的地址改成本站路径，并去掉请求里的 key 头。

路由表
------
  POST /api/        -> tronagg 下单
  GET  /api2/       -> tronagg 查订单
  GET  /api3/       -> tronagg 报价
  ANY  /trongrid/*  -> TronGrid 节点（自动带 key）
  其它               -> 静态页 index.html

部署（三选一，和之前一样）
==========================
方式一：wrangler（推荐）
  1. 解压后进目录（worker.js、wrangler.toml、public/ 同级）
  2. npm i -D wrangler
  3. npx wrangler login
  4. npx wrangler deploy
  5. 打开输出里的 https://<名字>.<子域>.workers.dev

  注意：这一版不需要再执行 wrangler secret put，key 已经在 worker.js 里了。

方式二：控制台建 Worker
  1. Workers & Pages -> 创建 Worker -> 把 worker.js 全部粘进去 -> Deploy
  2. Settings -> 静态资源（Assets），绑定名 ASSETS，指向 index.html 所在目录

方式三：Cloudflare Pages（拖拽）
  1. 把 worker.js 复制一份改名 _worker.js，和 index.html 放同一层
  2. 整个目录上传

换 key
------
  A) 直接改 worker.js 顶部两行常量，重新 deploy：
       const TRONAGG_KEY_DEFAULT = "新的 key";
       const TRONGRID_KEY_DEFAULT = "新的 key";
  B) 或者不改文件，用 Secret 覆盖（优先级高于写死的值）：
       npx wrangler secret put TRONAGG_KEY
       npx wrangler secret put TRONGRID_KEY
  两种都行；页面不用动、不用重传。

怎么确认部署成功
----------------
1. 页面能正常打开。
2. 打开   https://<你的域名>/api3/?resource_amount=100400&duration=1h
   应返回 JSON，里面有 "total_price_trx" 之类的报价。
3. 打开   https://<你的域名>/trongrid/wallet/getnowblock
   应返回一大段 JSON（包含 blockID、block_header）。返回 404 说明转发没接管这个路径。
4. 在页面上右键「查看网页源代码」，搜索 ta_ 和 ac3db086，都应该是 0 条。

注意事项
--------
- 这一版必须 worker.js 和 index.html 一起部署。只换 worker 不换页面：页面会继续
  直连 TronGrid（能跑，但 key 还留在页面里）；只换页面不换 worker：/trongrid 会 404，
  页面读不到余额。
- 如果访客的 TronLink 里手动配置了别的节点（不是 api.trongrid.io），那部分请求仍直连
  那个节点 —— 那是钱包自己的网络，本来就不涉及我们的 key。
- 密钥写在 worker.js 里，浏览器拿不到；能看到源码的只有你的 Cloudflare 账号。
  但如果这个包转发给别人，等于把 key 给了对方 —— 分享前先换 key。
