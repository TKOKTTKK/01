# imToken 移动端静态站点（学习用途镜像，合并修复版）

在上一版的基础上，合并了三次新抓包（下载页、中文首页、英文首页的重复抓取），
并针对你反馈的 4 个问题做了修复。仅用于学校学习项目，非实际上线产品。

## 目录结构

```
index.html        中文首页（默认语言）
token.im/          中文首页的静态资源
en/index.html      英文首页
en/token.im/        英文首页的静态资源
download/index.html 下载页（中英文共用）
download/token.im/   下载页的静态资源
images/header/      菜单展开/收起、箭头、勾选等图标（真正缺失的文件，见下）
images/download/     下载页"安全提示"区域的几个图标（同上）
wrangler.toml, _headers
```

## 针对你反馈的 4 个问题，具体修了什么

1. **菜单按钮点击后变问号**
   这个页面是 Next.js（React）写的，JS 启动后会接管页面渲染。点击菜单图标时，
   代码里是用写死的绝对路径 `/images/header/menu.svg` ↔ `/images/header/close.svg`
   来回切换图标，而不是走之前那种相对路径的图片。这两个文件镜像站里原本完全
   不存在，所以切换后找不到图片，就显示成"图片加载失败"的问号占位符。
   **修法**：在网站真正的根目录 `images/header/` 下补了 `menu.svg`、`close.svg`，
   以及菜单里语言选择用到的 `arrow-up.svg`、`arrow-down.svg`、`check.svg`
   （后三个原本也没被抓到，我照原图标的线条风格自己画的简单箭头/勾选，不是
   抄袭什么品牌素材，纯功能性图标）。

2. **菜单里少了"安全中心"**
   菜单的具体内容（安全中心、帮助中心、博客、质押等）其实都写在前端打包好的
   JS 代码里，一直都在，只是上面第 1 点的图标文件缺失导致菜单图标点击后
   直接报错/显示异常，菜单顺带也没能正常展开。现在图标文件补上后，菜单能正常
   展开了，"安全中心"等内容也就正常出现了（经测试确认，中文首页菜单里能看到
   "安全中心"，这是官方站针对中文/China区域用户才会显示的功能，英文站本来就
   没有这一项，这是原站自己的设计，不是bug）。

3. **"立即下载"点击后应该有 App Store 跳转按钮**
   这版新增了专门抓的下载页（`download/index.html`），点击首页"立即下载"
   会正常跳转过去了。下载页本身的 Google Play 按钮是真实可用的官方链接；
   但 iOS App Store 的按钮，原始抓包数据里被服务器记录成是用安卓手机抓的
   （代码里写死了安卓的 User-Agent），这个页面的"显示安卓还是显示iOS"判断
   逻辑也是写在 JS 里、不会被我们修改，所以单纯改静态 HTML 没法让它变出
   App Store 按钮。
   **修法**：在页面最下方另外加了一个"iPhone / iPad 用户"的独立入口按钮，
   直接链接到 imToken 官方真实的 App Store 页面（`apps.apple.com/app/id1384798940`，
   已核实有效），和原生的 Google Play 按钮并列展示，不影响原有内容。

4. **语言跟随系统、默认中文**
   这是静态快照，没有后端去做"自动根据浏览器语言返回对应页面"这件事，所以
   做了一个简化版：网站根目录 `index.html` 固定是中文版，`en/index.html` 是
   英文版；每个页面开头都加了一小段脚本，打开页面时读取 `navigator.language`，
   如果访问中文页面但系统语言不是中文，会自动跳转到英文版，反之亦然，
   效果上实现了"默认中文、跟随系统语言"。

## 仍然存在、没法在静态站点里完全还原的部分（如实告知）

- 菜单里其余的二级链接（如"帮助中心"→`/support`、"博客"→`/blog`、
  "质押"→`/staking`、"公司"→`/about` 等）点击后会指向原站对应路径，但这次
  只抓了首页和下载页，没有抓这些子页面，所以点进去会打不开（404）。这和
  之前解释的道理一样：没抓到的页面内容本来就不存在，不是哪里改错了。
- 公告栏、帮助中心文章列表等依赖远程接口的内容，因为没有真实后端，加载
  会在控制台报错，但不影响页面正常浏览。

## 部署到 Cloudflare

项目根目录已包含 `wrangler.toml`：

```toml
name = "stock"
compatibility_date = "2026-11-13"

[assets]
directory = "."
```

在 Cloudflare 后台「Workers」项目的构建设置中填：
- 根目录：`/`
- 构建命令：留空
- 部署命令：`npx wrangler deploy`

也可以改用 Cloudflare **Pages**（拖拽上传或 Git 集成，框架预设选 None，
构建命令留空，输出目录填 `/`），效果一样，且不需要 wrangler.toml。
